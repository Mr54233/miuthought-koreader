## 数据形状备忘(实现者必读)

- `api:search(q)` → unwrap 后典型 `{books={{bookInfo={bookId,title,author}},...}}`,但也见过直接 `{...}` 数组或 `results`;normalizer 必须防御。
- `api:chapters(id)` → unwrap 后典型 `{data={{chapterUid=1,title="第一章",chapterIdx=1},...}}` 或 `{updated={...}}` 或直接数组。
- `annotations:fetch_chapter(book_id, uid, progress)` → `{underlines=[], review_map={}, review_groups=[], underline_count=n, thought_count=n, thought_entry_count=n, errors=[]}`(网络重试在内部)。
- `Thoughts.save(store, book_id, chapter_uid, review_groups)`。
- `EpubInject.inject_copy(src, book_id, chapters, opts)`;chapters 每项 `{chapter_uid, href, underlines, review_map}`。
- 绑定存储:`store:get("bindings", {})` → `{[doc_path]={book_id,title,author,bound_at}}`。
- 文档标题:`self.ui.doc_props.display_title or self.ui.doc_props.title`,作者 `self.ui.doc_props.authors`;兜底文件名去后缀。

### Task 2: chapter_map.lua(引文投票章节映射)

**Interfaces:**
- `ChapterMap.normalize(html) → text`(剥标签、解常用实体、压缩空白;与引文同规则)
- `ChapterMap.quotes_of(underlines, limit) → {q1,...}`(取 markText/bookmarkText/rangeText/abstract,normalize 后长度≥6,按长度降序取前 limit=5)
- `ChapterMap.build(spine, read_text, chapters) → mapped, unmatched`
  - spine: `{{href,...}}`;read_text(href)→html(懒取,normalize 结果内部缓存)
  - chapters: `{{uid,title,underlines,review_map},...}`
  - mapped: `{{chapter_uid,href,underlines,review_map},...}`(仅命中者)
  - unmatched: `{{uid,title,reason="no_data"|"no_hit"},...}`
  - 算法:引文命中数最高的 href 胜(得分>0);0 分时章节标题(normalize 后≥2 字)在文中出现即兜底;无划线章节 reason=no_data。

**Steps:**
- [ ] 失败测试:两章分属两文件、引文跨实体(&amp;)命中、标题兜底、无数据/无命中、多个微信章节命中同一文件(顺序保留)
- [ ] 实现,全绿,Commit `feat: chapter_map — 引文投票映射微信章节到本地 spine`

### Task 3: epub_inject 同一 href 顺序叠加

**变更:** targets 构建循环删除 `targets[entry_path]` 冲突判定;改为 `local base = targets[entry_path] or EpubReader.read(...)`,apply 在 base 上叠加,marker_chapters 追加多条;同一 href 的 marks 分别按各章 count_marks(在该章 apply 后的增量:对 rendered 数该章 range 键)。后缀歧义仍 unmatched。

**Steps:**
- [ ] 更新原"同目标冲突"测试为合并语义:两章同 href 均注入,injected=2,两章锚点共存于该文件
- [ ] 实现,全绿,Commit `feat: epub_inject 支持多个微信章节叠加注入同一 spine 文件`

### Task 4: sync.lua(同步编排,依赖注入)

**Interfaces:**
- `Sync.run(deps) → report|nil, err`
- deps: `{doc_path, book_id, api, annotations, load_meta(path)→meta,err, read_text(meta,href)→html, save_thoughts(book_id,uid,groups), inject(src,book_id,chapters)→stats,err, progress(phase,i,n,text)→bool(false=取消)}`
- 流程:load_meta(拒绝 is_copy 由 inject 层负责)→ api:chapters → Binding.normalize_chapters → 逐章 fetch_chapter(progress "fetch")→ save_thoughts(有 review_groups 时)→ ChapterMap.build(progress "map")→ inject(progress "inject")→ report
- report: `{dest, injected, marks, thoughts_saved, chapters_total, chapters_with_data, unmatched={{uid,title,reason}}, fetch_errors=n}`
- 取消:progress 返回 false → 立即 `return nil, "已取消"`
- 全书无划线 → `nil, "这本书在微信读书里没有划线"`

**Steps:**
- [ ] 失败测试:mock api(chapters+underlines+readreviews 微信形状)走通全流程断言 report/save 调用/注入内容;取消路径;无划线路径;单章 fetch 报错不中断(计入 fetch_errors)
- [ ] 实现,全绿,Commit `feat: sync — 同步编排(拉取→缓存→映射→注入)`
